# 🔍 The Vindex (Preference Ranking) Project — Complete Guide

## What is Vindex?

**Vindex** is an **AI Model Response Evaluation Platform** built as a custom Odoo 18 module. Its core purpose is to enable human annotators (called "Taskers") to **compare and rate responses from two competing AI models** (referred to as Model A and Model B), while also benchmarking them against external commercial models (GPT 5.2 and Gemini 3 Pro). The ultimate goal is to determine which internal AI model produces better responses.

---

## 🔄 Complete Task Lifecycle (Step by Step)

### **Phase 1: Data Ingestion**

```
External JSONL File (URL) → POST /api/get_jsonl_data → Odoo Records Created
```

1. An **Admin** calls the API endpoint `POST /api/get_jsonl_data` with a **URL pointing to a JSONL file**.
2. Each line of the JSONL contains: [id](cci:1://file:///Users/macbookpro/My%20Work/grtlabs/GRT_LABS/odoo-18/custom_addons/valor/models/kimi_eval.py:83:0-84:46), [prompt](cci:1://file:///Users/macbookpro/My%20Work/grtlabs/GRT_LABS/odoo-18/custom_addons/valor/models/valor_turn.py:191:4-234:9), [response_a](cci:1://file:///Users/macbookpro/My%20Work/grtlabs/GRT_LABS/odoo-18/custom_addons/valor/models/generate_opalite_ophelia.py:254:0-345:17), [response_b](cci:1://file:///Users/macbookpro/My%20Work/grtlabs/GRT_LABS/odoo-18/custom_addons/valor/models/models.py:2772:4-2807:82).
3. The system applies **AB randomization**: 50% of the tasks have Response A and B swapped. This prevents position bias — the tasker doesn't know which model generated which response. The `is_randomized` flag tracks whether responses were swapped.
4. A `preference.ranking` record is created for each task.

### **Phase 2: AI Pre-Processing (Background)**

```
GET /api/get_llm_response → For each unprocessed task → Background Thread
```

1. An **Admin** calls `GET /api/get_llm_response`.
2. The system first fetches **router configuration** from the Meta GenAI API (`llm_annotations_model_router_workstream`), which returns [dialog_id](cci:1://file:///Users/macbookpro/My%20Work/grtlabs/GRT_LABS/odoo-18/custom_addons/valor/models/generate_opalite_ophelia.py:78:0-84:56), `model_1`, and `model_2`.
3. For each unprocessed task (`is_processed = False`), a **background thread** is spawned that performs:

   **a) Response Generation from Internal Models:**
   - Calls Meta GenAI API twice — once for `model_1` and once for `model_2` — using the task's prompt.
   - Stores the AI-generated Model A and Model B responses.

   **b) External Model Response Generation:**
   - Calls **Gemini** API to generate a response for the same prompt → stored as `gemini_response`
   - Calls **OpenAI GPT** API to generate a response → stored as `gpt_response`

4. After processing, the record is updated: `is_ratable = True`, `is_processed = True`.

### **Phase 3: Human Annotation (Tasker's Work)**

This is the core of what Vindex does. The **Tasker** opens a task in the Odoo form view and goes through these sections:

#### Section 1️⃣ — **Prompt Review**
- The tasker reads the `client_prompt` (rendered as Markdown/LaTeX).
- They decide: **"Is this prompt ratable?"** (toggle Yes/No).
- If not ratable, they select a **Rejection Reason** from categories:
  1. Image Handling
  2. Missing Reference Text
  3. Safety Concerns
  4. Gibberish/Nonsensical Content
  5. Contains PII
  6. Requires Localized/Real-Time Info
  7. Identity Requests
  8. Non-English Language

#### Section 2️⃣ — **Pointwise Rating of Response A**
The tasker reads **Response A** and rates it across **6 dimensions** (each on a 1-6 scale):

| Dimension | What it measures |
|---|---|
| **Truthfulness** | Factual accuracy, absence of hallucinations |
| **Instruction Following** | How well the response follows the prompt's instructions |
| **Writing Quality** | Clarity, grammar, structure, tone |
| **Verbosity** | Appropriate level of detail (not too long, not too short) |
| **Prompt Correctness** | Whether it correctly and completely answers the question |
| **Overall Quality** | Computed via weighted formula: [(IF × 0.25) + (Truth × 0.25) + (Correctness × 0.20) + (Writing × 0.15) + (Verbosity × 0.15)](cci:2://file:///Users/macbookpro/My%20Work/grtlabs/GRT_LABS/odoo-18/custom_addons/valor/models/models.py:360:0-3443:118) |

Each dimension has an **interactive rubric popup** that appears on hover, showing detailed scoring descriptors.

#### Section 3️⃣ — **Pointwise Rating of Response B**
Same 6 dimensions scored for Response B.

#### Section 4️⃣ — **AB Preference (Side-by-Side Comparison)**
- **AB Preference**: A -3 to +3 Likert scale:
  - `-3` = Response A is the absolute winner
  - `0` = Tied
  - `+3` = Response B is the absolute winner
- **AB Comment**: A written justification (1-3 sentences) explaining why one is preferred, citing specific dimensions and evidence.

#### Section 5️⃣ — **GPT 5.2 Comparison**
The tasker compares the **SxS winner** (the better of A/B) against GPT 5.2's response:
- **GPT Rubric Name** — Name a quality dimension (e.g., "Edge-case Handling")
- **GPT Rubric Description** — Describe it
- **GPT Rubric Scale Rating** — Rate 1-6 (absolutely no → absolutely yes)
- **AB GPT Preference** — -3 to +3 (internal winner vs GPT)

### **Phase 4: AI Evaluation & QC Check**

When an **Admin or Quality Lead** clicks the **"Evaluate"** button, the [eval_task()](cci:1://file:///Users/macbookpro/My%20Work/grtlabs/GRT_LABS/odoo-18/custom_addons/preference_ranking/models/models.py:444:4-1393:32) method runs:

#### Step 1: **AI Evaluation** (via `llm_actions.evaluation_for_tasks_sync`)
The system sends the prompt, both responses, and external model responses to the **Kimi AI model** (via Gemini API). It returns:

- **Pointwise scores** for Response A and B across all 6 dimensions → stored as `store_*` fields
- **AB preference and comment** → `store_ab_preference`, `store_ab_comment`
- **External model comparisons** → `store_ab_gpt_preference`, `store_ab_gemini_preference`
- **Rubric evaluations** → `store_gpt_rubric_name/description/rating`, `store_gemini_rubric_name/description/rating`
- **Reasoning** → `reason1_*` fields containing AI's justification for each score

#### Step 2: **Error Detection** (Rating Mismatch Check)
The system compares the **human's scores** with the **AI's scores** using a [check_error()](cci:1://file:///Users/macbookpro/My%20Work/grtlabs/GRT_LABS/odoo-18/custom_addons/preference_ranking/models/models.py:21:0-25:16) function. If they diverge significantly (difference > threshold), `error_*` flags are set to `True`, and a red **"Rating Mismatch"** alert appears in the UI showing the AI's reasoning.

For example, if the human gave `truthfulness_a = 6` but the AI gave `store_truthfulness_a = 2`, `error_truthfulness_a = True` and the AI's reasoning is shown.

#### Step 3: **Quality Control Checks** (via `llm_actions.perform_qc_checks_sync`)
Runs additional automated checks:
- **AB Preference-Comment Grounding**: Does the AB comment support the preference score?
- **AI Detection**: Are any human-written comments actually AI-generated? (Checks `ab_comment`, `ab_gpt_comment`, `ab_gemini_comment`, rubric names/descriptions)
- **Rubric-Comment Grounding**: Are the GPT/Gemini comments grounded in the actual responses?
- **External Preference-Comment Grounding**: Do the GPT/Gemini preference scores match their comments?
- **Rubric Rating Justification**: Are the rubric scale ratings justified?

Results → `qc_task_status = 'pass'` or `'fail'`, plus detailed reason fields.

#### Step 4: **Token Tracking**
Token usage and costs from both OpenAI and Gemini API calls during QC are recorded in `preference.ranking.token` records, tracking input/output/cached tokens and USD cost.
